### 1.2 ⚠️ 本机两条"静默失效"陷阱（本轮各踩一次，务必先读）

1. **本机 `grep` 是 toybox，不支持交替模式**（审查报告 §1.2 已记）：
   `grep -rl "A\|B" .` **静默返回空结果、不报错**。本轮我又踩了它的变体 ——
   `grep -q -e '…[{ type: …}]…'` 里的 `[` 被当成**字符类**，同样静默失配。
   ⇒ 锚定**代码字面量**一律用 `grep -qF`（固定字符串）。
2. **本机 `head` 是 toybox，不支持负参数**：`head -n -1` 报 `head: -n < 0` 并
   **静默产出空文件**。用它截断脚本会得到空脚本 ⇒ 后续断言全成"恒真"。

### 3.4 诚实登记：**本机跑不了真 vitest**

`pnpm install` 能成（`vitest 3.2.7` 已装），但 `vitest run` 起不来：

```
Error: The service was stopped:
  spawn …/@esbuild/android-arm64/bin/esbuild EACCES
```

根因：**Android 不允许 `exec` 应用私有目录里的文件**，而 esbuild 的原生二进制只能装在那里
（设备上唯一可 `exec` 的位置是 APK 的 lib 目录，那是只读的）。
⇒ 改用 `vitest-shim.mjs`（本地兼容层，覆盖 spec 实际用到的断言与 `describe/it` 语义）。
**因此仍有 4 个 spec 无法在本机跑**（用到 `vi.*` mock/spy）：
`login-poll-terminal-failure` / `loop-recovery` / `minimax-messages` / `probe-dispatch-guard`。
**这 4 个必须在 CI 上跑**（CI 的 ubuntu runner 没有该限制）。
