### 3.2 关键提交的实质（已读完整提交说明，非标题推断）

**① 网关 host 可配（`f10d1e58b9`）—— 安全与可用性并重**

- 动机：容器化部署下 host 硬编码 `127.0.0.1` ⇒ 端口映射**永不可达**；
- 主修：读 `DSH_OPENAI_GATEWAY_HOST`，**未设置时仍是 127.0.0.1**（零行为变化）；
- **连带安全**：新增「拒绝通配地址」判据，否则这条修复本身是安全倒退。

**② 通配判据连续修正（`aa2c4dbc` → `f92a0f7a`）—— 四版 fail-open 的收敛**

这是一条**独立审计驱动的安全修复链**，价值高于普通功能：

| 轮 | 做法 | 被证伪的原因 |
|---|---|---|
| 1 | `new URL()` 规范化 | 判据放行而内核真绑全网卡 |
| 2 | 枚举不可见字符码点 | `Cf` 有 160+ 码点，**枚举必漏**；`\u034f` 是 `Mn` 不是 `Cf` |
| 3 | Unicode 类别 + NFKC | `U+3002` 表意句号（`Po`，NFKC 不折）仍绕过 |
| 4 | **fail-closed 白名单** `/^[A-Za-z0-9.:%_-]+$/` | 实测未攻破（527,300 条候选穷举） |

**实测危害**（审计原文）：`0。0。0。0` 写法下，判据放行 → 网关真的启动 →
从**四个局域网接口**全部反连到 `HTTP 401`（暴露 4/4）。
Linux glibc 全 BMP 扫描命中 **12 个码点**全部真绑 `0.0.0.0`。

**③ trae 缓存（`c6565372`）—— 用户报障直接对应**

- 症状：用户报「trae 的缓存命中率一直是 0」；
- 根因：`token_usage` 分支只读 `prompt_tokens`/`completion_tokens`/`reasoning_tokens`，
  把上游**确实下发**的 `cache_read_input_tokens` **整对丢弃**；
- 为什么表现成「0」而非「—」：DSH 投影层做 `usage.cacheReadTokens ?? 0`
  ⇒ 字段缺席被归一成数字 0；
- 实测规模：本机 784 个真实会话中，trae 2397 条 usage 样本带 `cacheReadTokens` 的
  **0 条**，其余十三家为 76%~100% ⇒ **trae 是全机唯一的 0%**。

**④ zcode 额度按模型判定（`e8f8517f`）—— 用户报障直接对应**

- 症状：用户报「智谱送的 8M 分为 5.3-3M 和 5.3flash-5M，插件判账号没用完就不换号」；
- 根因：上游 `billing/balance` 的桶**按模型分**（实测
  `capabilities=["model:glm-5.3"]` / `["model:glm-5.3-flash"]`），旧判定未按模型归属；
- 落点：新增 `src/zcode-entitlements.ts`（408 行）。

## 六、风险与建议

### 6.1 若移植，必须注意（来自上游提交说明与本地约定）

1. **「上游新文件 = 可整文件覆盖」只对纯镜像文件成立**（9.23 教训）——
   网关两文件依赖更新的 `dsh-llm` 类型，整份覆盖会报类型错；
2. **新增 spec 必须同时登记** `rebuild-vendor.sh` 的 vitest 名单，否则**静默不跑**；
   本轮上游新增 3 个 spec：`openai-gateway-host-binding`、`zcode-captcha-upfront`、
   `zcode-model-entitlements`；
3. **本机 `patch` 命令不可靠**（多 hunk 漂移时整份静默跳过，不留 `.rej`）⇒
   一律用 node 脚本按精确锚点字符串替换；
4. **必须反向验证**（判别用例在旧树失败、新树通过才算证据）。

### 6.2 网关安全项的适用性判断（诚实标注）

手机版 `resolveGatewayConfig()` **目前不读** `DSH_OPENAI_GATEWAY_HOST`，
host 恒为 `127.0.0.1` ⇒ **通配绑定风险在手机版当前形态下不存在**。

因此该项的正确表述是：**不是「修手机版漏洞」，而是「引入 host 可配时必须同时引入防护」**。
若用户不需要容器化部署，**可只移植 fail-closed 判据**（防御未来改动），
或整体暂缓。**此点属产品判断，未擅自决定。**
