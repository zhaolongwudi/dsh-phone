## 3. 需要移植的：分两类处置

### 3.1 OfficeAce 全家桶 —— **建议暂缓**（本轮不移植）

**理由**（三条，均可查证）：

1. **依赖面横跨 Phase 6 重构**：`provider-registry.ts` + `credential-resolver.ts` + `createModelCatalog`
   骨架，手机版三项都**有意未采用**（成文记录在 `../porting/PORT-STATUS.md` §3.1）。为一个 provider
   补齐三处 Phase 6 基建，风险/收益比不成立。
2. **协议栈庞大**：华为云 OAuth（PKCE + DPoP，`dpop_private_key_jwk`）+ STS 30 天续期 +
   V11 签名余额直读 + 每日签到，共 2001 行新代码；手机版无该 provider 的既有用户。
3. **`login.ts` 的 144 行是 win32 专用**（`process.platform !== 'win32'` 直接 return）——
   照搬只会增加死代码。

**结论**：这是「**新增一个 provider**」，不是「修一个 bug」。是否要在手机版支持华为
ModelArts，属产品决策，**未擅自决定**。

### 3.2 DSML 归一化 —— **建议移植**（本轮未做，待确认）

这是本轮**唯一建议立刻移植**的项，理由：

- **它修的是「模型停住不动」这种用户直接可感的故障**，且**不依赖**任何 Phase 6 基建；
- `sse.ts` 手机版与上游旧基逐字节一致 ⇒ 77 行增量可安全叠加；
- 8 个适配器接线（openai-compat / zcode-anthropic / gemini-messages / minimax-messages /
  buddy / lobsterai / trae / llm-adapter）在手机版**全部存在**，接线面同构；
- **唯一要注意**：手机版这 8 个适配器与上游旧基有 6~426 行既有差异（有意差异：
  别名、死代码收敛），需逐个做语义移植，**不能整份覆盖**（上轮 §1.2 的同一条教训）。

**工作量估计**：`dsml.ts` 整文件新增 + `sse.ts` 77 行 + 8 个适配器各 20~40 行接线
+ 3 个 spec 移植登记 ≈ 与上轮 cline 自愈同量级。

> ⚠️ **注意**：`needsDsmlToolMode` 上游新版把判据从 `deepseek-v4-(flash|pro)` 扩到
> `deepseek-v4\.\d+-(flash|pro)`（即 `v4.1-flash`）。手机版只有 codearts/buddy 通道，
> 是否命中该扩展判据需实测确认 —— 若手机版根本不出现 `deepseek-v4.1-*` 模型，
> 归一化仍应移植（防的是「双竖线」笔误，与模型版本判据无关），但**提示构造的扩展
> 那部分可不带**。

## 4. 用户报障修复：菜单与侧边栏小按钮冲突

### 4.1 根因（三层证据链，全部代码层可查）

**第一层：那个「小按钮」是谁，以及它为什么总在**

上游 `dsh-client-ui-sidebar` 的 logoRow 里，toggle 的渲染分支是
`!darwinDesktop && toggle`（`lib/client.js` @22064 附近）；`isDarwinDesktop()` 判的是
`dataset.platform === 'darwin'`。**安卓不是 darwin ⇒ 该开关恒渲染**。折叠态下它是
36px 圆形小按钮（`.hHd-Xa_collapsed .hHd-Xa_toggle` 规则）——即用户说的「侧边栏小按钮」。

**第二层：为什么点它就出空白（与上轮同一个空白，不同触发路径）**

| 环节 | 值 | 出处 |
|---|---|---|
| 本层 CSS 侧栏容器宽 | `min(280px,86vw)` | `dsh-phone.css` @106 |
| 上游折叠态内容 | 文字叶节点 **23 → 0** | **真机实测**（§4.5）：文字全部消失，只剩图标 |
| 视觉症状 | 「左面空白，要再点一次小图标才出完整菜单」 | 即用户原话 |

上轮修的是「点菜单不出完整菜单」（上升沿没接上 ⇒ 侧栏停在折叠态）。
**本轮是同一空白的第二条触发路径**：上升沿修好后，用户又可以在抽屉里**手动**点小按钮
把侧栏折起来 —— 折完之后没有任何人会再展开它（上升沿只在抽屉「刚打开」时触发一次）。

**第三层：语义打架**

抽屉开着 ⇒ `data-dsh-drawer-open` 共享事实还在 ⇒ 菜单按钮 aria 显示「收起菜单」；
而侧栏实际是折叠的。两个控件对同一事物给出**矛盾陈述**。

### 4.2 修复（最小改动）

抽屉是**临时抽屉**，其存在期间侧栏没有「折叠」可言 —— 关抽屉即隐藏整个侧栏。
故打开态直接禁用该按钮：

```css
html[data-dsh-drawer-open] [data-dsh-rail] .hHd-Xa_toggle,
html[data-dsh-drawer-open] .pI_x6G_sidebarCol .hHd-Xa_toggle{display:none!important}
```

**为什么不选「折叠态时容器宽度跟随内容」**：那要改 280px 主规则 + transform 动画基准，
改动面大且会牵动 `settings-open` 常驻态；禁用一行规则即可消除全部三种症状。

**保留不动**：JS 里「点小按钮不关抽屉」的排除判据（`!target.matches(...)`）——
它防的是另一种失效（点小按钮误关抽屉），与本次隐藏是两道独立防线。

### 4.3 加固：apply.sh 两条新判据（含反向验证）

```bash
grep -qE "html\[data-dsh-drawer-open\][^{]*\.hHd-Xa_toggle[,{]" app/src/main/assets/dsh-phone.css
if grep -qE "\.hHd-Xa_toggle[A-Za-z0-9_-]" app/src/main/assets/dsh-phone.css; then
  echo "::error::上游 toggle 哈希被拼成变体（规则永不命中）"; exit 1
fi
```

**为什么是两条**（本轮实测，区分力逐个验证过）：

| 破坏方式 | 只查「drawer-open + toggle」 | 加上「无变体哈希」后 |
|---|---|---|
| 删掉整条规则 | ✅ 变红 | ✅ 变红 |
| 两条都丢掉 `drawer-open` 事实 | ✅ 变红 | ✅ 变红 |
| 哈希拼错成 `.hHd-Xa_toggleX` | ❌ **未检出**（前缀仍匹配） | ✅ 变红 |

> ⚠️ 第一版判据写的是 `[^{]*\.hHd-Xa_toggle`（无边界），反向实验证明它**分不出拼错的
> 哈希**——自检无区分力等于没有，故收紧到 `[,{]` 边界并补第二条。设备 grep 无 `-P`，
> 用不了 lookahead，这是不依赖它的等价做法。

### 4.5 真机验证（2026-10-13 21:30，CDP 仿真窄屏 412×915）

> 设备已装 **build-20261013-1307**（含本轮修复）。CDP 套接字本轮恢复可用
> （`webview_devtools_remote_11416`，pid 因重装而变）。

**① 修复是否生效（核心判据）**

| 时点 | drawerOpen | collapsed | toggleDisplay | toggleW |
|---|---|---|---|---|
| 基线（窄屏） | false | true | flex | 36 |
| **抽屉打开** | **true** | **false** | **none** | **0** |
| 关抽屉 | false | true | flex | 36 |

⇒ 抽屉打开时：侧栏**自动展开**（上轮上升沿修复仍在）、上游 toggle **被禁用**（display:none、宽 0）。
`document.elementFromPoint` 在该按钮原位命中 **header**（`wSkVaW_header`）而非按钮
⇒ 手指不可达，不只是视觉隐藏。

**② 空白/文字消失机制的真机度量**（用 `dispatchEvent` 绕过隐藏、强制折叠作对照）

| 形态 | collapsed | 文字叶节点 | 仅图标按钮 |
|---|---|---|---|

⇒ 折叠态的真实症状是**文字全部消失、只剩一排无标签图标**（contentRight 280→270），

（注：本轮报告初版曾据上游 `collapsedWidth=56` 推为「224px 空白」，真机证伪 ——
`inner root` 被本层 `width:100%!important` 撑到 280px，折叠只降密度不减宽度。已订正。）

**③ 宽屏未被误伤**（设备默认 1212px）

| 时点 | collapsed | toggleDisplay |
|---|---|---|
| 基线 | false | flex |
| 点菜单（代理） | **true** | flex |
| 再点一次 | **false** | flex |

⇒ 宽屏下上游折叠开关**照常工作**，菜单按钮代理有效，可来回切换。

**④ 设置面板钉住态刻意保留**

## 9. 本轮自查抓到的自身失误（如实记录）

| 1 | 用 bash heredoc 之外的 `node -e` 写含**反引号**的 CSS 注释 | bash 把反引号当命令替换，注释被吃掉 3 段 | 撤销污染段，改「先写文件再 node 应用」 |
