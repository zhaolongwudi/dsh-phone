## 3. 发现明细

### U-01（P1）暗色主题下的硬编码浅色配色 + 外部字体

**现象**：本层注入的 4 个可见元素写死了浅色系配色与 `system-ui` 字体，未消费 DSH 主题 token。同一文件里其它地方（如刚改过的菜单按钮）已统一改用 `var(--dsw-alias-*)` + `font:inherit`。

**证据**（逐处）：

| 位置 | 内容 | 呈现 |
|---|---|---|
| `dsh-phone.js:277` | `background:#eaf2ff;color:#2563eb;font:12px system-ui` | 输入区「投喂技能」按钮；`:285` 被「上传」按钮复用同一 cssText |
| `dsh-phone.js:280` | `color:#2563eb` | 上传/导入的状态提示行 |
| `dsh-phone.js:455-457` | `color:#626b78` + 链接 `#2563eb` | 「正在使用你的 ChatGPT 会员方案」提示 |
| `dsh-phone.css:274` | `background:#eef4ff;color:#2151a4;font:11px system-ui` | 远程执行徽标（`.dsh-peer-badge`） |

**影响**：暗色主题下这几处仍是浅蓝底/深灰字，与周围 DSH 控件不同族；`system-ui` 与 DSH 字体栈不一致 —— **与你 2026-10-18 确认过的「尺寸·字体·圆角不搭」是同一类问题的遗留**（当时只修了菜单按钮那两处）。

**建议**：改用主题 token（底色 → `--dsw-alias-bg-layer-2`、文字 → `--dsw-alias-label-primary/secondary`、品牌蓝需先查上游是否有对应 brand token），字体改 `font:inherit`。`dsh-phone.js` 是 APK 内置资源 ⇒ **需装包才见效**。

**风险**：低（纯视觉，无行为改动）。**验证**：窄屏 + 深色主题下看这 4 处是否与邻居同族（可先跑 `ui-live-verify.mjs --realapp --dark` 那 6 条深色判据做回归）。

### U-02（P1，**待实测确认**）宽屏形态几乎没有本层适配

**现象**：本层全部手机形态适配规则都在 `@media (max-width:767px)` 内（`dsh-phone.css:41-276` 的绝大多数）。而历史实测记录本机**主 WebView 视口是 1212×655（横屏/展开态）**，即 `mobileMedia:false` ⇒ **手机形态规则一条都不生效**。宽屏下本层仅剩 2 处逻辑：槽位开关代理给上游侧栏开关（`dsh-phone.js:252-260`）、ChatGPT 会员提示落点（`:442,453`）。

**证据**：
- `docs/porting/交接文档-给新会话.md:84`：「主 WebView 视口 **1212 × 655**（横屏；`screen` 1213×758，dpr 2.375）」
- `docs/porting/SHELL-UI-PORT-PLAN.md:1702` 实测快照：「仿真前：1212×655 · 断点不成立」
- `dsh-phone.css`：断点仅 767px 一档

**影响（推断，未实测）**：在这台折叠屏的**展开/横屏形态**下，用户看到的是上游桌面三列布局；本层针对手机做的收口（标题栏内边距、输入区尺寸、模型菜单定位、设置面板全屏化等）全部不参与。可用高度仅 655px 时，桌面布局是否会挤、输入区是否够用，**从未被系统审查过**。

**建议**：下一步先量这一个数——在展开态下取 `innerWidth/innerHeight`（CDP 恢复后一条命令即可），确认形态与可用高度，再决定是否需要新增一档宽屏矮窗适配（例如 `@media (min-width:768px) and (max-height:720px)`）。

**风险**：未确认前**不要动**（786 断点以上的改动影响所有宽屏用户，包括内置浏览器面板）。

### U-03（P2）注入文案全中文硬编码，无 locale

**证据**：`dsh-phone.js:275`（投喂技能）、`:283,292,294`（上传/上传图片/上传文件）、`:419`（上传图片/上传分析文件/导入技能）、`:438`（会员用量）、`:446`（电脑 · …）、`:510`（返回账号/选择供应商），以及 `MainActivity.kt` 对话框的「确定/取消」。

**影响**：上游与插件侧都有 locale 机制（`dsh-codearts-auth/locale/zh.json` 等），本层注入文案却恒为中文 ⇒ 界面语言切换后出现中英混杂。

**建议**：若你只用中文界面，可**明确不做**（记入「不做及理由」，避免将来被重新误做）；若要做，集中成常量表按 `document.documentElement.lang` 或 `navigator.language` 选择，不要散落。

### U-04（P2，已知项）同一功能两个侧栏开关

**证据**：实时 DOM 元素清单同时含 `{"text":"打开侧边栏"}`（上游侧栏内）与 `{"text":"☰"}`（本层注入）；宽屏代理逻辑见 `dsh-phone.js:252-260`。

**影响**：窄屏与宽屏都可能看到两枚做同一件事的按钮（其中上游那枚在抽屉打开时被 `dsh-phone.css:179-180` 隐藏，宽屏则不隐藏）。

**说明**：这是你 2026-10-18 已确认过的现象（见 `_ofm/UI-IMPROVE-PLAN.md` §1.1），当时只做了**视觉统一**、未消除重复。真要消除，最小改法是**宽屏不注入槽位开关**（让上游 toggle 独占），而不是用 CSS 隐藏本层按钮（会与「宽屏代理」设计打架）。

### U-05（P2）触摸目标偏小

**证据**：`dsh-phone.css:269`（输入区 `⋯` 开关 `min-width:28px;min-height:32px`）、`:264`（输入区工具行按钮 `min-height:32px`）、`:248`（会话日志按钮 30×30）、`dsh-phone.js:277`（内联 `padding:4px 7px` + 12px 字号，靠 `:264` 的 `min-height:32px` 兜到 32px）。

**影响**：手指点按容错偏低（44px 是通行触屏下限）。

**注意（不要盲目放大）**：本层已有成文取舍——`dsh-phone.css:101-103` 写明 badge 弹窗头部给 36px 会顶出横向溢出，故只给 32px。输入区一行要同时放下上传/投喂/模型选择/发送，**一律提到 44px 会溢出**。建议只处理空间充足处（会话日志按钮 30→32，与邻居对齐），其余保持并**把这条记成显式权衡**。

### U-06（P3）4 条死 CSS 规则

**证据**：`ui-anchors.json.knownDead` 登记 4 条；对应选择器在 `dsh-phone.css:48`（模型项描述换行，类名已被上游承载结构调整掉）、`:49`（分组标题换行）、`:257`（输入区内边距链中的两个类名之一）、`:258`（hero 态最小高度）。

**影响**：无用户可见影响（从未命中），属维护噪音 + 误导读码者以为生效。

**建议**：删除这些选择器片段（**注意 `:257` 要保留仍有效的那个前缀**），删后把 4 条从 `knownDead` 移除；改完跑 `check-ui-anchors.mjs`。
