## 2. 移植一：IKLIFH（工具结果图片必须与提问同在一条 user 消息）

**真实报障**「codebuddy hy4 不支持识别图片」。上游实测（直连 `copilot.tencent.com`）：

| wire 形态 | 上游行为 |
|---|---|
| 图与提问**同一条** user | ✅ 「左白右蓝」 |
| 图单独一条 user（有/无提示句），问在下一条 | ❌ 「图像已被过滤」/「不支持图片识别」 |
| 图并入 `role:'tool'` | ❌ 「不支持读取图片」 |

⚠️ 症状极具误导性：wire 上**确实有图**、上游也**不报错**（HTTP 200），只是模型
**看不见**并自称「当前模型不支持图片输入」⇒ 用户会误判成模型能力问题、反复换模型。

**修法**（三处同型实现同步：`openai-compat` / `buddy-adapter` / `lobsterai-adapter`）：
`flushToolImages` 增 `own` 形参把「同一轮要发的那条 user 消息」合并进同一条；
含工具结果的那条 user 消息**整条延后**（`pendingOwnParts`），排在 `role:'tool'`
之后发出；工具结果循环末尾**刻意不 flush**。

### 2.1 ⚠️ 对上游实现的**有意收窄**（实测的真实净回归）

上游 `flushToolImages` **无条件**把图排到文本之前。本仓库实测：那会翻转**普通贴图**
（无工具结果）的既有顺序 —— `[text, image]` 变成 `[image, text]`，使既有 spec 的
两条 order 断言变红（buddy / lobsterai 同型）。

顺序本身**不影响模型能否看见图片**（上游注释亦称「两种顺序实测都能被看到」），
故按最小改动原则收窄：**无挂图时 `own` 原样发出**（旧行为逐字节不变），
只有确实要「图与提问合条」时才做图前置重排。

## 3. 移植二：PR#93（minimax `tool-call-delta` 携带 name + 空名 tool_call 防线）

三件：

1. **`tool-call-delta` 必须携带 `name`** —— 它是网关侧 `function.name` 的**唯一来源**
   （`block-start`/`block-end` 在网关侧不消费）。漏发即标准 OpenAI 客户端
   （openai-node 的 zod 校验 / Codex / Cursor）抛
   `Expected 'function.name' to be a string`。
2. **名字不可用的 `tool_use` 整块丢弃、一个 chunk 都不产出** ——
   `BlockAssembler` 对没有 `block-end` 的 partial 照样组装出 `name: ''`，该空名块会被
   harness 执行成 `unknown tool ""` 并**持久化进会话**，之后切到别的 provider 时被每次
   重放 ⇒ HTTP 400 code 11133，整条会话报废。配套：`input_json_delta` 不为已丢弃块
   累积、`block-end` 去掉 `?? ''` 回退、同 index 后到的合法块要清标记。
3. **丢弃过空名块且一个可执行调用都没发出**时，finish 报 `max-tokens`（可重试）
   而非 `tool-calls`（会让 harness 等一个永远不存在的工具调用）。

## 4. 移植三：IKLI7J（`login.poll` 终态失败通道）

**真实报障**「任何 provider 登录失败都只剩 5 分钟静默转圈」。两条根因：
后端失败侧回 `{done:false, error}` 或删掉占位条目，而前端 `if (!pollRes?.done) return;`
**只判 `done`**，把唯一指路的原因整体丢掉；删条目后又与「用户还没授权完」同形。
5 分钟是**客户端自己的轮询上限**。

**服务端**（`jet-hub-rpc.ts`）：
- 新增 `loginFailures` 终态表（TTL 30 分钟 / 上限 256 / **读后不删**，保证幂等）；
- 新增 `failLogin` 统一收尾，**先判「凭据是否已落库」**（已落库 ⇒ 这次登录就是成了，
  只记日志、不删号不报错 —— 上游两轮独立审计查出的净回归）；「读不到池」返回
  `'unknown'` ⇒ 只记终态、**不删账号**（删除不可逆）；
- 11 处 provider 后台失败收尾全部改走 `failLogin`；4 处同步抛错保留 `removeAccount`；
- `login.poll` **在查账号池之前**先查终态表。

**客户端**（`plugin-src/client/jet-hub.js`）：**先判 `success === false`、再判 `done`**；
超时分支必须给提示且文案**不得写死成「未完成授权」**；轮询请求本身失败必须留痕。

### 4.1 手机版形态适配（如实标注，非逐字节照搬）

- 手机版 `registerJetHubRpc` 仍是**位置参数**（上游本轮改成具名对象）；
- 上游新增的 `officeace` / `accio` 两个 provider **不引入**（第七轮决议）⇒
  上游用 OfficeAce 作失败替身的用例，这里改用 **codearts / gemini**；
- 本面板的 create 流程没有可用的 `setError`/`setPhase`（错误文案只在 `'error'`
  阶段渲染，而该流程运行时 phase 恒为 `'ready'`）⇒ 失败提示走
  `setProbeNotice({tone:'error'})`，与同文件既有的两条提示同一出口。

### 4.2 ⚠️ 由此产生的一处**新缺陷**（本轮审查中修复，见 §6.2）

改用 `setProbeNotice` 后必须补 `await loadAccounts()` / `loadCredits()` 才能刷新，
而 `stopPoll()` 原先排在这两个 await 之后 ⇒ 给 1 秒轮询留下重入窗口。

## 6. 项目审查发现的**三处真实缺陷**（用户要求「检查当前项目 bug」）

方法与判据：**结构扫描**（node 读文件，不用不可靠的 grep/diff）+ **行为探针**
（在真实编译产物上调导出的纯函数）。审查脚本：`.scratch/round-20261014/x/audit-all.mjs`。

### 6.1 ★★ 延后的正文被静默丢弃（真实数据丢失）

`combined` 的判据写成「有挂起工具图片 **或** 本条自己有图」，**漏了 `pendingOwnParts`**。

```
某条 user 含工具结果  ⇒ 它自身正文被延后进 pendingOwnParts
紧接着的下一条 user 若既无挂图、自己也无线
  ⇒ combined === undefined
  ⇒ flushToolImages(undefined) 因「无挂图且 own 为空」提前 return
  ⇒ 那份延后正文从未被发出
```

**实测（修复前探针）**：`[text("工具的说明正文") + tool-result]` 之后跟普通 user
「追问」，wire 上只剩「追问」。另一条同源路径：同一条 user 既带**顶层图片**又带工具
结果时，顶层正文与顶层图片**三项全丢**。

**上游同段逐字节等价、同样存在**（`slice(up) === slice(ph)` 实测为 true）——
判为「上游同源既有缺陷」，但它是真实数据丢失，按用户「修 bug」的要求一并修掉：
三处判据补 `|| pendingOwnParts !== undefined`。

> ⚠️ 该缺陷在移植前**不存在**（旧实现把带工具结果那条的正文直接发出）；是本轮
> 引入「整条延后」后暴露的边界，故属本轮必须一并修掉的范围。

### 6.2 ★ 客户端终态失败分支的 `stopPoll()` 排在 `await` 之后

见 §4.2。修法：`stopPoll()` 提到分支最前，与超时分支同构。

### 6.3 审查复核（未发现问题的面，逐条留档）

| 面 | 结论 |
|---|---|
| 后台失败收尾接线 | `account.create` 全部 **11 处** `.catch` 都接到 `failLogin`（0 漏接） |
| 同步抛错路径 | 4 处保留 `removeAccount`（前端立刻收到 throw，无需终态表） |
| 三处 `flushToolImages` | 五件结构齐全（own 形参 / 收窄 / 合条 / deferred / 纯文本字符串） |

## 8. ⚠️ 本轮抓到的**验证手段自身**缺陷（留档）

1. **反向验证驱动的污染**：驱动把破坏版 `plugin-src` 留在沙箱，下一轮未重铺 ⇒
   后续几组出现同型**假红**（表现为「与破坏无关的客户端断言也红」）。
   修法：每轮开始先从未破坏的 `overrides` 全量重铺。
2. **沙箱 `out/src/*.ts` 陈旧**：`resync` 原先只在文件缺失时才复制，于是 spec 的
   源码断言读到**修复前**的形态（既会假红也会假绿）。修法：改为**强制覆盖**。
3. **源码断言的注释自匹配**：IKLIFH 的「循环末尾不得 flush」判据先用裸文本扫描，
   而修复注释里**引用**了 `flushToolImages` ⇒ 判据把注释当代码、真实现改了也照样绿。
   修法：先 `stripComments` 再判（与 IKLI7J 的计数守卫同一纪律）。
4. **行锚定正则的转义**：多轮脚本传递中 `\s` 的反斜杠被吃掉，导致 `^s*` 这种
   永不匹配的正则（判据静默失效）。修法：改用文件写入而非 shell 内联字符串。
5. **`indexOf` vs 行锚定**：`stopPoll()` 在注释里也出现，`indexOf` 命中注释。
   修法：一律用行锚定正则 `^\s*stopPoll\(\);?$`。

> 共同点与既有教训一致：**验证手段本身不可信**比被测对象有缺陷更危险，
> 因为它会把结论**反向报告**（假绿与假红同级危险）。
